01 / Why it exists

Keep your data within your rules.

A local model still runs through applications, helpers, and child processes. AI Guard is built around that complete application scope: define what it may read, what it may change, and where it may connect, then review its activity in one workspace.

01

Protect your files

Set path rules for read, write, read only, or deny. Use explicit defaults to define the boundary around a model workflow.

02

Control connections

Keep network access and endpoint rules with the application profile, so connectivity is a deliberate part of the workflow.

03

See the complete app

Review related executables, helpers, and observed child processes together. Keep policy and activity close to the application they belong to.

04 / Your data

Privacy,
in plain language.

Read the privacy policy ↗

  • Local policies

    Application profiles and access policies are kept on the Mac. AI Guard does not upload model prompts or file contents to a developer service.

  • Activity metadata

    Local activity history can contain application identities, paths, endpoints, and access decisions. Treat diagnostic exports as private.

  • Background service

    The application uses a privileged local service for access decisions. macOS permissions and the supplied build determine which integrations are available.
